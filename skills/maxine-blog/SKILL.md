# Maxine 双语博客

## 任务入口

- 写作、翻译、文章迁移、分类、URL 或元数据工作：阅读 [内容与双语规范](references/content.md)。
- 页面设计、布局、样式、组件或视觉检查：阅读 [UI 规范](references/ui.md)。
- 同时涉及文章和页面时读取两份参考；单纯修正文案无需重新设计页面。

## 项目约定

- 定位：以长期写作为核心的双语个人主页，内容围绕工具、学习与实践。品牌显示名暂定 `Maxine’s Notes`，中文可用「Maxine 的笔记」；不要为普通文章任务顺带改站名或虚构作者背景。
- 使用现有 Jekyll + Markdown + GitHub Pages 基础，优先复用共享布局、组件和样式。
- 用户已选择小红书感的红白配色，取代旧的米白深绿方向。具体色值是本项目设计值，不宣称为小红书官方规范，也不使用其商标冒充品牌。
- 当前实现使用自定义 Jekyll 布局，双语文章位于 `_posts/zh/` 与 `_posts/en/`；界面文案和分类使用 `_data/*.json`，共享样式位于 `assets/css/main.css`，交互位于 `assets/js/main.js`。先检查实际代码，区分已实现能力和目标规划。
- 写作应进入博客内容系统，避免新增携带整套导航与内联样式的独立 HTML 文章。若所需基础设施尚不存在，按用户授权范围补齐必要部分，或明确说明缺口；不要把未接入的页面称为可发布成品。
- 用户指定的语言、主题、格式和后续设计变更优先；仅要求中文文章时不自动生成英文全文。

## 执行与交付

1. 检查相关现有文件与未提交改动，确定此次任务是内容、翻译、UI 还是基础设施。
2. 读取适用参考，在当前实现上工作。保留现有文章和可用链接，迁移时安排旧路径兼容。
3. 按改动检查：文章元数据与链接、译文配对、当前语言列表、移动端排版、交互状态。使用 `bundle exec jekyll build` 构建，再运行 `python3 scripts/check_site.py` 检查生成页面；UI 变更另做浏览器检查。纯规范编辑无需构建网站。
4. 交付实际修改的文件、验证结果及仍未实现的相关能力。创建或修改文件不等于提交、推送或部署；只有用户要求时才执行发布相关操作。

## 建设顺序

- 先建立双语路径、共享模板、首页／博客／关于页与语言切换，迁移现有内容并保留旧链接。
- 再完善红白 UI、主题筛选、长文目录、相关文章、双语 RSS 和 SEO 元数据。
- 随内容增长加入搜索、分页、系列和项目页；评论与统计按需要接入。
- 普通博客任务只完成相关范围，不把以上路线图当作每次必须执行的清单。
